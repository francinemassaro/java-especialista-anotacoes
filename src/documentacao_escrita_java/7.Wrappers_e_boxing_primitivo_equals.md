
# Tipos Primitivos vs Wrappers no Java

Quase tudo em Java é objeto, **mas não os tipos primitivos**.

Algumas vezes a gente precisa enxergar os tipos primitivos também como uma **classe**, como por exemplo caso precise colocar ela como `null`, caso não tenha a informação.

As **classes wrappers** embrulham o valor do tipo primitivo dentro dela pra gente tratar eles como objeto.  
Ela embrulha um próprio valor do tipo primitivo dentro dela.

As classes wrappers têm alguns tipos de métodos que a gente pode usar:

```java
Integer diasParaEntrega;
Long codigoEntrega;
Float valorFrete;
Double valorTotal;
Character tipoCliente;
Boolean compraPaga;
```

---

## a) Comparando primitivos vs wrappers

- Tipo primitivo é ok comparar com `==` porque ele pega o valor, mas também compara o tipo.

**Exemplo:**  
Comparar `int` com `int` com os mesmos valores → dá `true`  
Comparar `int` com `double` com os mesmos valores → dá `false`

---

### Wrappers: usar sempre `.equals`

Se usar `==` com wrappers (como `Integer`), ele compara os objetos em memória.  
Objetos com valor acima de 128 são armazenados em locais diferentes da memória, então o `==` dá `false`.

```java
Integer numero1 = 128;
Integer numero2 = 128;

numero1 == numero2;         // FALSE
numero1.equals(numero2);    // TRUE
```

Também vale lembrar que `.equals` compara **valor e tipo**.

```java
Integer numero1 = 128;
Short numero2 = 128;

numero1.equals(numero2);                        // FALSE (tipo diferente)
numero1.intValue() == numero2.intValue();       // TRUE (convertendo pra primitivo)
```

---

## b) Quando usar wrapper e quando não usar?

- Primeira coisa: **nunca comparar valores de wrapper com `==`**. Use sempre `.equals`.
- Sempre dê preferência a tipos primitivos, porque eles são mais rápidos.
- Use **wrapper** quando **não for possível usar o primitivo**.
- Use **wrapper** quando precisar que seja atribuído **valor `null`** à variável.
